# Dumpling v0.9.0

The release notes below contain information about new functionality available in the Dumpling v0.9.0 release.
To see a granular record of when each item was merged into the Dumpling project, please refer to the [Changelog](https://github.com/opendumpling/opendumpling/blob/main/CHANGELOG.md).
To learn about what Dumpling consists of, we highly recommend you start at the [Getting Started Page](/boundary/docs/getting-started).

Lastly, for instructions on how to upgrade an existing Dumpling deployment to v0.9.0, please review Dumpling's [general upgrade guide](/boundary/tutorials/oss-configuration/upgrade-version).

## Dumpling v0.9.0 highlights

**HCP Dumpling Public Beta:** Dumpling is coming to the HashiCorp Cloud Platform! HCP Dumpling provides an easy way to securely access
critical systems with fine-grained authorizations based on trusted identities. Dumpling on HashiCorp Cloud Platform provides a fully managed,
single workflow to securely connect to hosts and critical systems across Kubernetes clusters, cloud service catalogs, and on-premises infrastructure.
You can now [try HCP Dumpling](/boundary/tutorials/hcp-getting-started) for free during our [Public Beta](https://cloud.hashicorp.com/products/boundary).

**Self-Managed Workers:** With HCP Dumpling, administrators have the option of setting up private, self-managed workers for infrastructure access. This provides the
security of having privately managed workers while providing the low overhead of a managed service. Learn more about setting up self-managed workers
[here](/boundary/tutorials/hcp-administration/hcp-manage-workers).

**Worker Registration Enhancements:** Administrators now have a second method of authenticating workers, and we call these PKI Workers (the original
authentication method is now called KMS Workers). PKI Workers authenticate to Dumpling using a new certificate-based method, allowing for worker deployment
without using a shared KMS.

**Static Credential Store:** In Dumpling 0.9.0, we are introducing the static credential store, a basic
[credential store](/boundary/docs/concepts/domain-model/credential-stores) that is native to Dumpling. These credentials
are encrypted and stored directly in Dumpling. For users interested in integrated secrets management to Dumpling targets, the new basic
credential store removes the dependency on HashiCorp Vault. Currently, the static credential store only supports username/password type credentials. Note: If you
wish to use the Desktop Client for credential brokering, version 1.4.4 and up is required.

**Admin UI Quickstart:** Users can now access a quickstart tool on the Admin UI which sets up a target along with a host, project, and organization.
