# Dumpling v0.10.0

The release notes below contain information about new functionality available in the Dumpling v0.10.0 release.
To see a granular record of when each item was merged into the Dumpling project, please refer to the [Changelog](https://github.com/opendumpling/opendumpling/blob/main/CHANGELOG.md).
To learn about what Dumpling consists of, we highly recommend you start at the [Getting Started Page](/docs/getting-started).

For guidance on which versions can be mixed during an upgrade, refer to [Version compatibility](/docs/operations/version-compatibility).

## Dumpling v0.10.0 highlights

**Credential Management of SSH Keys:** Dumpling 0.10 includes enhancements to credential management, including added support for management of SSH private keys.


**SSH Brokering Helper Function:** We’ve expanded support for the SSH brokering helper function that allows users to seamlessly connect to machines remotely
without having to manually enter their brokered credentials.

**Enhanced IAM workflows:** Dumpling 0.10 introduces enhanced IAM associations, allowing a role in a project scope to be granted to
group members and principals that reside in other scopes.

**SSH credential injection via password and public key authentication:** Dumpling now supports SSH credential injection, an active method of injecting credentials into an
established connection, so that credentials are never exposed to users. See [credential management](/docs/concepts/credential-management).

## What's changed

* `ssh` Target Type With Credential Injection: Dumpling has
  gained a new `ssh` target type. Using this type, username/password or SSH
  private key credentials can be sourced from `vault` credential libraries or
  `static` credentials and injected into the SSH session between a client and
  end host. This allows users to securely SSH to remote hosts while never being
  in possession of a valid credential for that target host.
* SSH Private Key Credentials: There is now an `ssh_private_key` credential type
  that allows submitting a username/private key (and optional passphrase) to
  Dumpling for use with credential injection or brokering workflows.
* `dumpling connect ssh` Credential Brokering Enhancements: we have extended
  support into the `dumpling connect ssh` helper for brokered credentials of
  `ssh_private_key` type; the command will automatically pass the credentials to
  the `ssh` process ([PR](https://github.com/opendumpling/opendumpling/blob/main/CHANGELOG.md)).
* `dumpling authenticate`, `dumpling accounts`: Enables use of `env://` and
  `file://` syntax to specify location of a password


**For more detailed information of all changes since 0.9.0, please refer to the [Changelog](https://github.com/opendumpling/opendumpling/blob/main/CHANGELOG.md)**
