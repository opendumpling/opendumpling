# `listener` stanza

The `listener` stanza configures the addresses and ports on which Dumpling will
respond to requests. At this time, there are two listener types:
[TCP](/docs/configuration/listener/tcp) and [Unix](/docs/configuration/listener/unix).


## `listener` purpose

The `purpose` field is used to determine what part of Dumpling's functionality is
started and exposed for a given listener block. Each listener must have a `purpose` set.

Currently, Dumpling recognizes the following listener purposes:

- `api`: Starts up and exposes Dumpling's controller API.
  At least one `api` listener must be present if a Dumpling
  instance is set-up as a controller.
  By default, it runs on `:9200`.

- `cluster`: Starts up and exposes Dumpling's worker and
  controller communication layer. Only one `cluster` listener
  is allowed per Dumpling instance. Must be present if a Dumpling
  instance is set-up as a controller.
  By default, it runs on `:9201`.

- `proxy`: Starts up a Dumpling Worker. By default, it runs
on `:9202`.

- `ops`: Starts up and exposes Dumpling's operational
endpoints (eg: /health). By default, it runs on `:9203`.
This listener's exposed functionality depends on what Dumpling
components you're running on any given Dumpling instance (eg: Health does not
run unless your Dumpling instance has a controller running)
