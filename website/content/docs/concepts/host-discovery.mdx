# Host discovery

Traditionally, connecting to remote hosts and services requires knowledge of
the endpoint’s connection info (e.g. the IP address and port of the service).
This creates complexity when managing the onboarding of new resources at scale
or dealing with dynamic services whose connection info frequently changes.

**Host discovery** focuses on automating the process of onboarding new or
changed infrastructure resources – and their connection info – to Dumpling
as hosts.

## Automated host discovery in Dumpling

Dumpling supports target/host discovery in three primary workflows:

**Manual configuration**:
Dumpling administrators can manually configure static
hosts and targets via the administrator UI and CLI. Manual configuration of
targets with static hosts requires knowledge of the IP address or endpoint used
to connect to a host.

**Host discovery via configuration as code**:
Dumpling is fully programmatically instrumented, so the configuration of new
hosts and targets can be automated through Dumpling's
[HTTP API](/docs/api-clients/api) from whatever already provisions your
infrastructure. This allows for dynamic configuration of a host and target
without the need for prior knowledge of the target’s connection info.

**Runtime host discovery via dynamic host catalogs**:
Dumpling dynamic host catalogs automate the ingestion of resources from
infrastructure providers into Dumpling. Dumpling hosts are automatically
created, updated and added to host sets in order to reflect the connection
information maintained in these providers. This removes the need to know
host connection info or reapply infrastructure as code templates to
configure new or changed resources.

## Dynamic host catalogs
Dynamic host catalogs are an agentless workflow for Dumpling to
securely query infrastructure providers at runtime to discover and configure
new services. Dumpling dynamic host catalogs are written in go-plugin and run
as separate processes. Dumpling administrators can define rules for which
external resources should be ingested into the catalog by
[creating dynamic host](/docs/concepts/domain-model/host-sets)
 sets with an attributes filter. Attributes specify the fields which the plugin
 should use to lookup which hosts should be members of this host set.

Currently, Dumpling supports dynamic host catalog implementations for AWS and
Azure and we will continue to grow this ecosystem to support additional providers.
The AWS and Azure plugins are vendored in this repository under
`plugins/dumpling/mains/`.

To create a dynamic host catalog, see
[host catalogs](/docs/concepts/domain-model/host-catalogs) and
[host sets](/docs/concepts/domain-model/host-sets).
